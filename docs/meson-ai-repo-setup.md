# Meson AI — Repo Setup Guide

The how to go with the blueprint's why. Assumes the recommended stack: Turborepo + pnpm monorepo, Next.js App Router, Supabase CLI. Standalone variant at the end.

## 1. Prerequisites

* Node 22 LTS (via `nvm`/`fnm` — pin with `.nvmrc`)
* pnpm 9+ — `corepack enable && corepack prepare pnpm@latest --activate`
* Supabase CLI — `brew install supabase/tap/supabase`
* Turborepo — installed as a dev dep, no global needed
* The `meson-database` project ref (Supabase dashboard → Project Settings → General). You'll need it for `supabase link`.

## 2. One-shot init sequence

Run top to bottom from an empty folder:

```bash
# Workspace root
mkdir meson-platform && cd meson-platform
git init && pnpm init
echo "22" > .nvmrc

# Workspace + tooling
pnpm add -Dw turbo typescript prettier eslint @supabase/ssr
mkdir -p apps packages/{ui,db,config} supabase

# The app
cd apps
pnpm create next-app@latest meson-ai \
  --ts --tailwind --eslint --app --no-src-dir \
  --import-alias "@/*" --use-pnpm
cd ..

# Supabase (single source of truth lives here)
supabase init
supabase link --project-ref <meson-database-ref>

# App's Supabase client deps
pnpm --filter meson-ai add @supabase/supabase-js @supabase/ssr @tanstack/react-query
```

Then create the config files in §3–§4 and the first migration in §6.

## 4. Shared packages

Keep anything Next-specific out of these so AgentPhone (possibly non-Next) can reuse them too.

`packages/config` — the shared brain

* `tsconfig.base.json` — strict base, extended by every package/app
* `eslint.config.js` — flat config (ESLint 9), shared rules
* `tailwind-preset.js` — the liquid-glass tokens baked in once so Meson AI matches Ploutos: charcoal `#0a0a0c`, indigo `#6366f1`/`#818cf8`, `Inter` + `JetBrains Mono`, Tabler icons. The app's `tailwind.config` just does `presets: [require('@meson/config/tailwind-preset')]`.

`packages/db` — typed data layer

```
packages/db/src/
  types.ts      # generated by `pnpm db:types` — never edited by hand
  index.ts      # re-exports Database type + shared, framework-agnostic queries
```

```ts
// packages/db/src/index.ts
export type { Database } from './types'
// shared query builders that accept a typed client, e.g.
// export const getAccounts = (sb: SupabaseClient<Database>) => sb.from(...)
```

`packages/ui` — the design system (built later, scaffolded now)

* `name: "@meson/ui"`, exports components consumed via `import { Button } from '@meson/ui'`

Each package gets a minimal `package.json` (`"name": "@meson/db"` etc.) and extends `@meson/config`.

## 5. The app — Supabase client split + route protection

The cookie wiring depends on Next's `cookies()`, so it stays in the app, not `packages/db`.

`apps/meson-ai/lib/supabase/client.ts` (browser)

```ts
import { createBrowserClient } from '@supabase/ssr'
import type { Database } from '@meson/db'

export const createClient = () =>
  createBrowserClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
  )
```

`apps/meson-ai/lib/supabase/server.ts` (server — Next 15 `cookies()` is async)

```ts
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'
import type { Database } from '@meson/db'

export async function createClient() {
  const store = await cookies()
  return createServerClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll: () => store.getAll(),
        setAll: (toSet) => {
          try { toSet.forEach(({ name, value, options }) => store.set(name, value, options)) }
          catch {}
        },
      },
    }
  )
}
```

`apps/meson-ai/middleware.ts` — refresh session + gate `(app)/*`

```ts
import { type NextRequest } from 'next/server'
import { updateSession } from '@/lib/supabase/middleware'

export const middleware = (req: NextRequest) => updateSession(req)
export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|webp)$).*)'],
}
```

`lib/supabase/middleware.ts` holds `updateSession`: it refreshes the auth token and redirects unauthenticated users away from app routes to `/login`. This is your server-side gate — don't rely on client checks alone.

Server-only secret: `SUPABASE_SERVICE_ROLE_KEY` is read only inside route handlers / server actions, never imported into a client component.

## 6. Supabase wiring & the isolation-first first migration

After `supabase init` + `link`, the first migration establishes tenancy and RLS before any feature table exists — so nothing ever ships without isolation.

```bash
pnpm db:new init_meson_ai_foundation
```

```sql
-- supabase/migrations/<ts>_init_meson_ai_foundation.sql
create schema if not exists meson_ai;

create table meson_ai.accounts (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  plan text default 'trial',
  status text default 'active',
  partner_id uuid,                         -- white-label hook (decide before launch)
  owner_id uuid references auth.users(id),
  created_at timestamptz default now()
);

create table meson_ai.account_members (
  account_id uuid references meson_ai.accounts(id) on delete cascade,
  user_id uuid references auth.users(id) on delete cascade,
  role text not null default 'member',
  primary key (account_id, user_id)
);

-- membership helper (security definer avoids recursive RLS)
create function meson_ai.current_account_ids()
returns setof uuid language sql security definer stable as $$
  select account_id from meson_ai.account_members where user_id = auth.uid()
$$;

-- enable + FORCE rls, default deny
alter table meson_ai.accounts        enable row level security;
alter table meson_ai.accounts        force  row level security;
alter table meson_ai.account_members enable row level security;
alter table meson_ai.account_members force  row level security;

create policy account_member_read on meson_ai.accounts
  for select using (id in (select meson_ai.current_account_ids()));
```

Then:

```bash
supabase db push        # apply to meson-database
pnpm db:types           # regenerate packages/db/src/types.ts
```

Expose the schema: Supabase dashboard → API → add `meson_ai` to Exposed schemas, and grant the app role usage. Do not expose internal `public` tables to the app role.

Edge functions live in `supabase/functions/` (`crm-sync`, `campaign-orchestrator`, `airwallex-webhook`) and deploy with `supabase functions deploy`.

## 7. Env & secrets

`apps/meson-ai/.env.local` (gitignored)

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=        # or the new sb_publishable_... key
SUPABASE_SERVICE_ROLE_KEY=            # server only — never NEXT_PUBLIC
# provider OAuth (HubSpot, Salesforce…), Airwallex keys, etc.
```

Commit a `.env.example` with empty keys. Supabase's newer `sb_publishable_*` / `sb_secret_*` keys work too — anon/service-role are still valid.

## 8. Netlify deploy (monorepo)

`netlify.toml` at root:

```toml
[build]
  command = "pnpm turbo build --filter=meson-ai"
  publish = "apps/meson-ai/.next"

[[plugins]]
  package = "@netlify/plugin-nextjs"
```

Set the site's base directory to the repo root in the Netlify UI; the `--filter` keeps it building only the Meson AI app. Edge functions deploy via the Supabase CLI, not Netlify.

## 9. Migration-ownership rule (the operational landmine)

This monorepo's `supabase/migrations` is now the single source of truth for the shared `meson-database`. Ploutos must stop running its own migrations against this DB independently, or you'll get drift and conflicts. Pick one: either Ploutos's migrations move here too, or you draw a hard schema boundary (`public` = Ploutos, `meson_ai` = this app) and agree nobody migrates the other's schema.

## 10. First-run checklist

1. [ ] `pnpm install` at root resolves the workspace
2. [ ] `supabase link` points at meson-database (not Ploutos's ref)
3. [ ] First migration applied; `meson_ai` schema exposed in API settings
4. [ ] `pnpm db:types` populates `packages/db/src/types.ts`
5. [ ] `.env.local` filled; service-role key server-only
6. [ ] `pnpm dev` boots the app; middleware redirects to `/login` when logged out
7. [ ] Decide white-label tenancy before adding feature tables (cheap now)

## Standalone variant (if you skip the monorepo)

Drop `apps/` and `packages/`. The `meson-ai` app sits at root with its own `supabase/` folder. Pull the design system + DB types in as a private package or git submodule so they don't drift from Ploutos. Everything else — client split, middleware, migrations, RLS, env — is identical.
